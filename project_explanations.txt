به نظر من، **ترکیب Graph Neural Networks با Mechanistic Interpretability می‌تواند پروژه بسیار مناسبی برای رزومه تو باشد**؛ چون دو حوزه‌ای را به هم متصل می‌کند که در هر دو تجربه پژوهشی داری.

## **۳.۲. تعریف یال‌های گراف**

سه نوع ارتباط می‌توانیم داشته باشیم.

**Inter-layer Edges:** ارتباط یک لایه با لایه بعدی برای همان paraphrase.

\\[ (v\_{p,l},v\_{p,l+1}) \\]

این ارتباط مسیر تغییر بازنمایی‌ها در طول عمق مدل را نشان می‌دهد.

**Cross-paraphrase Edges:** ارتباط بازنمایی‌های paraphraseهای مختلف در یک لایه یکسان.

\\[ (v\_{p,l},v\_{q,l}),\quad p\neq q \\]

این ارتباط کمک می‌کند الگوهای مشترک مستقل از نحوه بیان سؤال را بررسی کنیم. در نسخه اولیه، تمام paraphraseها در یک لایه به یکدیگر متصل می‌شوند.

**Similarity Edges:** ارتباط میان بازنمایی‌هایی که در فضای embedding شباهت بالایی دارند.

\\[ w\_{ij}=\frac{h_i^\top h_j} {\\|h_i\\|\\|h_j\\|} \\]

این نوع یال را در نسخه دوم اضافه می‌کنیم و تأثیر آن را با ablation study می‌سنجیم.

توجه کن که شباهت بین دو بازنمایی به معنای رابطه علّی بین آن‌ها نیست. این یال‌ها فقط ساختار تحلیلی پیشنهادی ما هستند.

# **۴. استخراج ویژگی‌های گره‌ها**

برای هر paraphrase یک Forward Pass روی LLM انجام می‌دهیم.

در نسخه اولیه، hidden state آخرین توکن ورودی، درست قبل از تولید پاسخ، را از تمام لایه‌ها ذخیره می‌کنیم.

\\[ h\_{p,l}\in\mathbb{R}^{2048} \\]

ویژگی اولیه هر گره می‌تواند شامل موارد زیر باشد:

| ویژگی                               | ابعاد پیشنهادی |
| ----------------------------------- | -------------- |
| Residual stream representation      | 2048           |
| Normalized layer position           | 1              |
| Activation norm                     | 1              |
| Activation sparsity                 | 1              |
| Cosine similarity to previous layer | 1              |
| Prediction entropy از Logit Lens    | 1              |

در نتیجه هر گره در این پیکربندی ۲۰۵۳ ویژگی خواهد داشت.

پیشنهاد می‌کنم برای شروع از hidden representation به‌تنهایی استفاده کنی و ویژگی‌های آماری را بعداً اضافه کنی تا تأثیر هر گروه از ویژگی‌ها قابل اندازه‌گیری باشد.

## **۴.۱. کاهش ابعاد**

\\[ z\_{p,l}=W\_{\text{proj}}h\_{p,l}+b \\]

\\[ 2048\rightarrow256\rightarrow128 \\]

دو روش را مقایسه کن:

- PCA بدون آموزش نظارت‌شده، که فقط روی داده‌های train برازش شده است.
- Learnable Linear Projection، که همراه GNN آموزش می‌بیند.

## **۴.۲. استخراج Activationها با PyTorch**

کد اولیه برای استخراج hidden states بسیار ساده است:

# **۵. معماری Graph Neural Network**

پیشنهاد من این است که چهار معماری زیر را مقایسه کنی:

| معماری    | نقش در پروژه             |
| --------- | ------------------------ |
| GCN       | Graph baseline           |
| GraphSAGE | Graph baseline           |
| GATv2     | Attention-based baseline |
| R-GCN     | معماری پیشنهادی اولیه    |

چون گراف ما انواع مختلف یال دارد، Relational GCN انتخاب منطقی است.

## **۵.۱. پیکربندی پیشنهادی**

**Input graph**

128 nodes × 2048 features

**Input projection**

2048 → 256

**R-GCN Layer 1**

256 → 128 + LayerNorm + GELU

**R-GCN Layer 2**

128 → 128 + Residual connection

**R-GCN Layer 3**

128 → 128 + Residual connection

**Query-conditioned Pooling**

128-dimensional graph representation

**Answer Ranking Head**

128 → LLM hidden size → Vocabulary

معادله message passing:

\\[ h_i^{(k+1)}= \sigma\left( W_0^{(k)}h_i^{(k)} + \sum\_{r\in R} \sum\_{j\in\mathcal N_r(i)} \frac{W_r^{(k)}h_j^{(k)}}{c\_{i,r}} \right) \\]

به این ترتیب مدل برای ارتباط‌های بین لایه‌ها و ارتباط‌های میان paraphraseها وزن‌های متفاوتی یاد می‌گیرد.

## **۵.۲. چرا از Global Mean Pooling استفاده نکنیم؟**

چون هدف ما صرفاً تشخیص دانش در مجموعه paraphraseها نیست. می‌خواهیم یک اجرای خاص را که در آن پاسخ اشتباه تولید شده، بررسی کنیم.

بنابراین یکی از promptها به‌عنوان **Target Prompt** مشخص می‌شود و Readout نسبت به آن شرطی خواهد بود.

\\[ z\_{\text{target}} =\sum\_{i\in V}\alpha_i h_i \\]

که در آن وزن‌های pooling با توجه به بازنمایی Target Prompt محاسبه می‌شوند.

برای جلوگیری از وابستگی بیش‌ازحد به paraphraseهای دیگر، در زمان آموزش می‌توان تعدادی از viewها را به‌صورت تصادفی حذف کرد (View Dropout).

# **۶. خروجی GNN چه چیزی باشد؟**

این قسمت از نظر علمی بسیار مهم است. نباید فقط یک classifier داشته باشیم که خروجی Known یا Unknown تولید کند، چون برای دانش واقعی مدل ground truth دقیقی نداریم.

پیشنهاد من تعریف دو وظیفه پژوهشی است.

## **Task A: Hidden Answer Recovery**

GNN تلاش می‌کند پاسخ صحیح را از بازنمایی‌های داخلی LLM بازیابی کند.

برای مثال:

**سؤال:** What is the capital of Germany?

**Original LLM**

Paris

62%

Berlin

13%

Munich

10%

London

5%

Other

10%

**GNN Probe**

Berlin

81%

Paris

9%

Munich

5%

London

2%

Other

3%

احتمال‌های فرضی برای نمایش خروجی مورد انتظار؛ نتیجه تجربی واقعی نیستند.

برای اینکه مدل GNN خودش تبدیل به یک بانک دانش نشود، پیشنهاد می‌کنم از Unembedding Matrix ثابت LLM استفاده کنی.

\\[ \hat h=W\_{\text{out}}z\_{\text{target}} \\]

\\[ \hat y=\operatorname{softmax} (W_U\hat h) \\]

که \\(W_U\\) همان وزن‌های ثابت LM Head است.

تابع هزینه:

\\[ \mathcal L\_{\text{answer}} =-\log P\_{\text{GNN}}(y^\*) \\]

البته ثابت نگه داشتن LM Head به‌تنهایی جلوی یادگیری دانش جدید توسط GNN را نمی‌گیرد. بنابراین کنترل‌های بخش ارزیابی ضروری هستند.

## **Task B: Knowledge Evidence Estimation**

در این بخش به‌جای تصمیم قطعی درباره اینکه مدل چیزی می‌داند یا نمی‌داند، میزان شواهد را اندازه‌گیری می‌کنیم.

| وضعیت                       | تفسیر                                            |
| --------------------------- | ------------------------------------------------ |
| Expressed Knowledge         | مدل مستقیماً پاسخ درست می‌دهد                    |
| Accessible but Inconsistent | مدل فقط به بعضی paraphraseها پاسخ درست می‌دهد    |
| Internally Decodable        | پاسخ درست از بازنمایی‌های داخلی قابل استخراج است |
| No Evidence Found           | روش‌های فعلی شواهد کافی پیدا نکرده‌اند           |

دسته آخر به معنی اثبات نبود دانش نیست.

این تعریف با چارچوب مقاله Inside-Out هم ارتباط نزدیکی دارد؛ آن مقاله دانش داخلی و خارجی را براساس توانایی رتبه‌بندی پاسخ‌های درست و غلط مقایسه می‌کند.&#x20;

# **۷. طراحی هوشمندانه‌تر: تفکیک دو حالت آزمایش**

این بخش می‌تواند یکی از مهم‌ترین نقاط قوت پروژه باشد.

### **حالت اول: Single-Prompt Graph**

GNN فقط به بازنمایی‌های همان سؤالی دسترسی دارد که مدل به آن پاسخ اشتباه داده است.

در این حالت گراف فقط شامل لایه‌های یک prompt است.

### **حالت دوم: Multi-Prompt Graph**

GNN به بازنمایی‌های هشت paraphrase دسترسی دارد، اما هیچ پاسخ تولیدشده یا پاسخ صحیحی را به‌عنوان ورودی دریافت نمی‌کند.

**Single-Prompt**

آیا دانش در اجرای ناموفق قابل استخراج است؟

**Multi-Prompt**

آیا شواهد ترکیبی میان اجراها قابل استفاده است؟

اگر Multi-Prompt موفق شود ولی Single-Prompt شکست بخورد، نمی‌توانیم ادعا کنیم دانش در همان اجرای ناموفق وجود داشته است؛ شاید اطلاعات از paraphrase دیگری بازیابی شده باشد.

به همین دلیل هر دو حالت باید جداگانه گزارش شوند.

حتی می‌توان یک مجموعه paraphrase مستقل را کنار گذاشت که GNN هیچ‌وقت آن‌ها را نبیند و فقط برای ارزیابی رفتاری استفاده شوند.

# **۸. اضافه کردن Mechanistic Interpretability واقعی**

تا این مرحله یک Graph-based Probe ساخته‌ایم، اما هنوز نمی‌توانیم بگوییم سازوکار واقعی مدل را کشف کرده‌ایم.

برای این کار سه آزمایش علّی اضافه می‌کنیم.

## **۸.۱. Layer Importance**

به‌صورت جداگانه هر لایه یا گروهی از گره‌های آن را از گراف حذف می‌کنیم و میزان تغییر عملکرد GNN را محاسبه می‌کنیم.

\\[ I_l=S(G)-S(G\setminus V_l) \\]

که \\(S\\) امتیاز پاسخ موردنظر است.

این تحلیل مشخص می‌کند GNN برای پیش‌بینی خود به چه لایه‌هایی وابسته است.

اما اهمیت یک گره برای GNN الزاماً به معنی اهمیت آن برای خود LLM نیست؛ باید این نتیجه را روی LLM اعتبارسنجی کنیم.

## **۸.۲. Neuron Attribution**

در لایه‌های منتخب، به‌جای بررسی همه نورون‌های مدل، می‌توان Integrated Gradients یا Gradient × Activation را روی MLP activations محاسبه کرد.

برای مثال:

\\[ A_i=a_i\frac{\partial m}{\partial a_i} \\]

که در آن:

\\[ m=\operatorname{logit}(\text{Berlin}) -\operatorname{logit}(\text{Paris}) \\]

این تابع نشان می‌دهد تغییر فعالیت هر نورون در جهت پاسخ درست یا اشتباه چه اثری دارد.

پاسخ صحیح در این بخش صرفاً برای تحلیل آزمایشگاهی با دسترسی به برچسب استفاده می‌شود؛ نه به‌عنوان ورودی GNN یا یک روش بازیابی بدون اطلاع از پاسخ.

## **۸.۳. Causal Intervention**

در اجرای اصلی ناموفق، فعالیت نورون‌های منتخب را تغییر می‌دهیم.

\\[ a_i'=\gamma a_i \\]

- اگر \\(\gamma=0\\) باشد، Ablation انجام داده‌ایم.
- اگر بین صفر و یک باشد، فعالیت نورون را کاهش داده‌ایم.
- اگر بزرگ‌تر از یک باشد، فعالیت موجود را تقویت کرده‌ایم.

### **شبیه‌سازی مفهومی مداخله روی نورون‌ها**

مزیت این آزمایش آن است که برخلاف انتقال activation از paraphrase موفق، تلاش می‌کنیم همان فعالیت موجود در اجرای ناموفق را تغییر دهیم.

برای معتبر بودن نتیجه، باید با مداخله روی نورون‌های تصادفی، نورون‌های دارای activation مشابه و لایه‌های غیرمنتخب مقایسه انجام دهی.

## **ساختار داده پیشنهادی**

```
{
  "fact_id": "fact_00001",
  "subject": "Germany",
  "relation": "capital_of",
  "object": "Berlin",
  "paraphrases": [
    "What is the capital of Germany?",
    "Germany's capital city is",
    "Which city is the capital of Germany?",
    "Name Germany's capital city."
  ],
  "negative_candidates": [
    "Paris",
    "London",
    "Rome"
  ]
}
```

فیلدهای `object` و `negative_candidates` فقط برای supervision و evaluation هستند و نباید مستقیماً به ویژگی‌های گراف وارد شوند.

## **تعداد نمونه‌ها**

| نسخه پروژه         | تعداد حقایق | تعداد paraphrase |
| ------------------ | ----------- | ---------------- |
| Debug              | 100         | 4                |
| MVP                | 1,000       | 6                |
| Full experiment    | 5,000       | 8                |
| Research extension | 10,000+     | 8–16             |

برای MVP ابتدا حقایقی را انتخاب کن که جوابشان در tokenizer مدل یک توکن باشد. این کار محاسبه و مقایسه logits را ساده‌تر می‌کند. بعداً می‌توانی با sequence log-likelihood از پاسخ‌های چندتوکنی نیز پشتیبانی کنی.

# **۱۰. مهم‌ترین مسئله: Data Leakage**

اگر این پروژه خوب طراحی نشود، ممکن است GNN خودش حقایق جهان را یاد بگیرد و تمام نتیجه علمی زیر سؤال برود.

### **تقسیم‌بندی صحیح داده**

### **Fact-disjoint split**

15%

15%

تمام paraphraseهای یک حقیقت باید فقط در یکی از سه مجموعه قرار بگیرند.

علاوه بر تقسیم‌بندی معمول، چهار آزمایش تعمیم‌پذیری را در نظر بگیر:

| Split             | هدف                                            |
| ----------------- | ---------------------------------------------- |
| Fact-disjoint     | حقایق تست در آموزش مشاهده نشده‌اند             |
| Subject-disjoint  | موجودیت‌های موضوع تست در آموزش مشاهده نشده‌اند |
| Relation-disjoint | نوع رابطه تست در آموزش مشاهده نشده است         |
| Template-disjoint | ساختار زبانی promptهای تست جدید است            |

حتی باید نسخه‌ای از آزمایش داشته باشی که موجودیت پاسخ نیز بین train و test مشترک نباشد، اگر تعداد داده اجازه دهد.

## **آزمایش کنترل برای تشخیص دانش یادگرفته‌شده توسط GNN**

یک مجموعه حقایق مصنوعی با موجودیت‌های ساختگی و پاسخ‌های تصادفی بساز.

مثلاً:

```
The capital of Zanovia is Meron.
The capital of Trevania is Solvik.
The capital of Valdoria is Norven.
```

دو checkpoint آزمایشی داشته باش:

| مدل                | وضعیت                                  |
| ------------------ | -------------------------------------- |
| Base model         | بدون آموزش روی حقایق مصنوعی            |
| LoRA-adapted model | آموزش روی زیرمجموعه‌ای از حقایق مصنوعی |

باید تخصیص پاسخ‌های مصنوعی تصادفی و کنترل‌شده باشد تا از طریق نام موجودیت یا فراوانی پاسخ قابل حدس نباشند. بخشی از حقایق نیز هرگز به مدل معرفی نشوند.

سپس بررسی کن آیا GNN می‌تواند تفاوت میان حقایق معرفی‌شده و معرفی‌نشده به مدل را تشخیص دهد.

این آزمایش به تو یک کنترل آزمایشگاهی می‌دهد که در دیتاست‌های جهان واقعی وجود ندارد. البته معرفی یک حقیقت در fine-tuning نیز تضمین نمی‌کند مدل آن را به‌طور کامل یاد گرفته باشد؛ باید موفقیت یادگیری را جداگانه بررسی کنی.

# **۱۲. معیارهای ارزیابی**

## **معیارهای بازیابی دانش**

| Metric                    | کاربرد                                |
| ------------------------- | ------------------------------------- |
| Accuracy                  | درصد پاسخ‌های صحیح                    |
| Hits\@1                   | قرار گرفتن پاسخ صحیح در رتبه اول      |
| Hits\@5                   | قرار گرفتن پاسخ صحیح در پنج رتبه اول  |
| MRR                       | میانگین معکوس رتبه پاسخ صحیح          |
| Pairwise Ranking Accuracy | مقایسه رتبه پاسخ‌های درست و غلط       |
| AUROC                     | تشخیص وضعیت‌های دارای برچسب کنترل‌شده |
| ECE                       | ارزیابی calibration                   |
| Paraphrase Consistency    | پایداری پاسخ در برابر تغییر بیان سؤال |

معیار اصلی پیشنهادی من **Recovery Rate on Failed Prompts** است.

\\[ RR= \frac{ \\#(\text{LLM wrong, Probe correct}) }{ \\#(\text{LLM wrong}) } \\]

در کنار آن باید مواردی را هم گزارش کنی که LLM پاسخ درست داده، اما probe آن را اشتباه کرده است.

## **معیارهای آزمایش علّی**

\\[ \Delta m=m\_{\text{after}}-m\_{\text{before}} \\]

که \\(m\\) اختلاف logit پاسخ صحیح و پاسخ غلط است.

همچنین باید نرخ اصلاح واقعی پاسخ، میزان تخریب پاسخ‌های قبلاً درست و تأثیر مداخله بر حقایق نامرتبط را گزارش کنی.

| --------------- | ------------------------------------ |

| مدل 7B با 4-bit | قابل بررسی؛ محدودیت برای attribution |

پیشنهاد من این است که نسخه اصلی را با BF16 اجرا کنی تا quantization رفتار activationها را تغییر ندهد.

برای مثال، ذخیره hidden state آخرین توکن از ۲۰۰۰ حقیقت، ۸ paraphrase، ۱۶ لایه و ۲۰۴۸ بعد، در BF16 حدود یک گیگابایت فضای ذخیره‌سازی نیاز دارد. البته logits کامل، activationهای تمام توکن‌ها و attention tensorها می‌توانند حجم داده را به‌شدت افزایش دهند.

GNN را بعد از استخراج و ذخیره ویژگی‌ها، مستقل از LLM آموزش بده. این کار استفاده از GPU را بسیار بهینه‌تر می‌کند.
